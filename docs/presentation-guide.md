# ROUTE 발표자 가이드

ROUTE는 제한된 시간과 교통비, 일부 모드의 체력 안에서 이동 수단과 경로를 선택하는 웹 퍼즐 게임이다. 발표자는 이동 선택이 필요한 이유, 서버의 판정 방식, 경로 탐색의 기준, 진행 데이터의 저장 위치를 설명할 수 있어야 한다.

## 프로젝트 소개

> ROUTE는 도보·버스·지하철의 시간과 비용을 비교하며 목적지까지 자신만의 경로를 찾는 턴제 경로 퍼즐 게임입니다. 선택한 경로를 기준 경로와 비교하고, 같은 지도에서 다시 도전하며 선택을 개선할 수 있습니다.

기본 흐름은 모드 선택, 미션 확인, 인접 역 선택, 이동 수단 선택, 서버 판정, 결과 확인, 경로 복기다. 이동할 때만 게임 시간이 소비되므로 플레이어는 자원을 비교하며 생각할 수 있다.

## 발표 전에 숙지할 개념

| 개념 | 설명 |
| --- | --- |
| 노드·간선 | 역이 노드, 역 사이 구간이 간선이다. 간선마다 이용 가능한 이동 수단과 시간이 다르다. |
| 시간·돈·체력 | 도보는 무료지만 느리고 체력 소모가 크다. 교통수단은 시간을 줄이지만 요금과 구간 조건을 고려해야 한다. 체력은 해당 설정이 있는 모드에 적용한다. |
| 환승 | 기본요금은 지하철 1,550원, 버스 1,500원이다. 환승 잔여 시간이 있으면 다음 대중교통 요금은 무료이고 이동 시간에 3분을 추가한다. 대중교통 이동 후 잔여 시간은 30분으로 갱신되고 도보 이동 시간만큼 줄어든다. |
| 별점 | 레벨 모드에서 도착, 목표 시간 또는 심부름 완료, 교통비 또는 체력 절약을 각각 평가한다. 추가 두 목표는 도착 성공을 전제로 독립적으로 평가한다. |
| 효율·등급 | 별점과 별도로, 성공 시 기준 경로 시간과 실제 이동 시간의 비율로 계산한다. 효율은 최대 100%다. |
| 기준 경로 | 게임 규칙과 탐색 상태 모델에서 계산한 경로다. 화면에서는 ‘최적 경로’로 표시한다. 실제 도시의 최단 경로를 뜻하지 않는다. |

## 모드와 선택의 의미

- **레벨 모드:** 15개 레벨을 순차 해금한다. 날씨·컨디션·시간 여유가 달라지며, 레벨 5·7·13·15에는 사건, 6·10·14에는 경유 미션이 있다.
- **상황별 캠페인:** 비·파업 등 서로 다른 조건의 캠페인 3종이다.
- **일주일 등교:** 월요일부터 금요일까지 저금·지각·친구 도움·우산 구매가 다음 날 조건에 연결된다. 실패한 날에도 다음 날로 진행할 수 있다.
- **무한 모드:** 라운드에 따라 지도와 제약이 변한다. 현재 서버는 라운드 입력을 1~30으로 제한하므로 ‘무제한 라운드가 보장된다’고 설명하지 않는다.

교통 사건은 해당 이동의 출발 시각을 기준으로 적용한다. 일주일 모드에서는 친구를 돕지 않았을 때 특정 사건의 정확한 발생 시각이 숨겨질 수 있다. 심부름은 선택 목표이며, 성공한 경우 수행 여부에 따라 도착 이야기가 달라진다.

## 기술 설명 순서

1. **화면:** HTML·CSS·순수 JavaScript로 구성하고, SVG로 역과 구간을 그린다. SVG의 좌표 영역을 바꿔 지도 확대와 이동을 처리한다.
2. **통신:** 브라우저가 Fetch API로 JSON 요청을 보내고 Express 서버가 상태와 결과를 돌려준다.
3. **판정:** 서버가 인접 역인지, 해당 수단을 이용할 수 있는지, 돈과 체력이 충분한지 확인한 뒤 이동을 적용한다. 화면의 비용 표시는 서버 견적을 사용한다.
4. **알고리즘:** 최소 힙을 이용한 다익스트라 기반 탐색에 역·사용 자금·환승 잔여 시간·체력·경유 여부를 상태로 포함한다. 같은 역에 도착해도 자원 상태가 다르면 다음 선택이 달라지기 때문이다.
5. **저장:** 규칙은 JSON, 설정·별점은 브라우저, 진행 중 게임은 서버 메모리, 결과 기록은 서버 JSON 파일에 저장한다. 별도 DB는 없다.

구체적인 필드와 요청 구조는 [기술 및 데이터 구조](technical-overview.md)에 정리되어 있다.

## 권장 시연 순서

1. `npm ci`로 설치하고 `npm start`로 서버를 실행한 뒤 브라우저를 연다.
2. 첫 레벨의 미션과 자원을 설명하고, 생각하는 동안 시간이 줄지 않는 것을 보여 준다.
3. 구간의 시간 표시를 비교하고 역을 선택해 수단 카드의 시간·요금·체력을 설명한다. 카드는 누르면 즉시 이동하므로 미리 확인한다.
4. 도착 후 별점 목표와 효율 등급의 차이를 설명한다. 실패하면 같은 지도 재도전과 기준 경로 재생을 보여 준다.
5. 해금된 사건·경유 레벨이나 일주일 등교를 이용해 단순 최단거리 외의 선택을 보여 준다. 일주일 모드의 다음 날 진행으로 선택의 영향을 연결한다.

후반 레벨을 보여 줄 계획이라면 시연 브라우저의 레벨을 미리 해금해 둔다. 지도는 무작위로 생성되므로 특정 역·경로·완주 시간을 발표의 고정 예시로 약속하지 않는다. 브라우저 새로고침과 서버 재시작은 시연 중 진행을 끊을 수 있다.

## 예상 질문과 답변

| 질문 | 답변 |
| --- | --- |
| 실제 지도나 대중교통 API를 연결했나요? | 아니다. 설정의 역 이름을 사용해 게임용 그래프를 생성한다. 실제 거리·운임 체계·실시간 지연을 재현하는 서비스는 아니다. |
| 왜 단순 최단거리 계산으로 충분하지 않나요? | 같은 역에 도착해도 사용한 돈과 체력, 환승 잔여 시간, 경유 여부가 달라지면 가능한 다음 이동이 달라지기 때문이다. |
| 계산한 경로는 언제나 절대적인 최적해인가요? | 탐색 모델 기준 경로다. 체력은 탐색 시 5단위로 보수적으로 계산하므로 실제 체력 판정에서 가능한 일부 경로가 탐색에서 제외될 수 있다. |
| 서버가 필요한 이유는 무엇인가요? | 맵 생성·경로 계산·비용 차감·성공 판정을 한곳에서 처리하고, 화면은 같은 규칙으로 계산된 견적을 표시하기 위해서다. |
| 재도전하면 조건이 바뀌나요? | 같은 지도 재도전은 지도·출발·목적지·초기 자원·사건 조건을 유지하고 이동 상태를 초기화한다. 새 게임은 새 지도를 생성한다. |
| 회원가입이나 DB가 있나요? | 없다. 레벨 기록은 이 브라우저에 저장하며, 다른 기기로 동기화하지 않는다. |
| 새로고침 후 이어 할 수 있나요? | 현재 화면은 세션 복원을 지원하지 않는다. 같은 탭에서 홈과 게임 사이를 오갈 때 이어 하기를 지원한다. |
| 테스트가 보장하는 범위는 무엇인가요? | `npm test`로 27개 DOM·API 연동 검사를 수행한다. 실제 브라우저의 팝오버 위치·화면 겹침·터치 정확도는 별도 확인 대상이다. |

## 구현 범위와 확장 방향

현재 구현은 경로 선택, 자원 관리, 조건별 미션, 경로 복기와 재도전에 초점을 둔다. 로그인·기기 간 동기화·새로고침 후 세션 복원·실제 교통 연동·이동 되돌리기는 구현되어 있지 않다.

운영을 확장한다면 DB 기반 진행 저장, 다중 서버의 세션 공유, 접근 제어, 부하 측정과 브라우저 검증이 필요하다. 이 항목들을 구현 완료 기능이나 검증된 성능으로 발표하지 않는다.
